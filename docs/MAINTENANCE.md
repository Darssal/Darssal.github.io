# 主页内容与发布维护

本站用于展示沈瑚双 / Darssal 的真实教育、科研、获奖与开源经历。维护时优先保证访客可以快速了解本人背景、研究问题、个人贡献和相应证据，再调整排版与文案。

## 论文与作者

- 标题、作者顺序、期刊或会议名称、年份、DOI 等依据论文正式页面和作者材料核对；本人姓名可加粗，不能重新排列作者。
- 第一作者、共同第一作者、通讯作者等角色仅在论文或明确材料支持时标注。共同第一作者保留等贡献说明。
- 分别标注已发表、已录用、预印本、在投和研究中。录用通知支持“已录用”，不能据此写成已出版论文或编造 DOI、页码和会议展示形式。
- 目前主页的论文定位为 2 篇第一作者 SCI-E 期刊已发表论文、1 篇共同第一作者 IEEE SMC 已录用论文。状态变化后同步更新首页、公开简历和验证页。
- 论文外链优先指向期刊、会议、DOI 或正式检索页。尚无公开全文时保留已核实的书目信息，不上传私有稿件、审稿通信或录用通知原件。

## 结果与代码

论文实验结果应保留数据集、任务、指标和原文适用条件。论文报告的结果、公开代码可复现的结果和仅通过代码检查的部分应分别表述；没有运行实验就不能声称已经复现模型性能。

例如单元测试通过数表示测试覆盖范围，不能写成模型精度。合成样本上的演示分数不能写成真实业务收益。训练、推理或验证使用上游实现时保留归属，并说明本人实现或维护的模块；不将依赖框架功能全部归为个人创新。

方法示意图用于解释流程，不代替实验结果图。更新图像时核对内容、可读性和替代文本；图片不含原始数据、未公开材料或联系方式。

当前本科身份与 2027 级 UCAS／ICT 保研去向分别展示；未来去向紧邻注明尚未入学，不推断学位类型、导师或毕业年份。新立项时序 Transformer 项目按在研和 2026.06—2027.06 计划周期维护，现有信息不支持具体个人角色、架构、数据规模或效果指标。已结题项目保留项目成员身份与 2026.09 结题日期，不将其贡献转移至新项目。

- 团队奖应保留团队性质；队长、负责人或个人贡献有证据后再标注。参赛、入围与获奖分别描述。
- 优先链接官方比赛介绍或公开公示；不上传证书原件、证书编号、身份证号或其他个人信息。材料只证明奖项时，不延伸为大厂录用或企业工作经历。

- 他人主页用于参考信息结构与排版。参考作者的公司、机构、奖项、照片和成果不进入本人的履历。

## 公开信息范围

公开简历只包含经授权的职业与学术事实，不包含手机、邮箱、家庭或宿舍地址、身份证信息。本站无需收集访客的联系方式。照片使用本人可公开的照片，不从论文、证书或第三方主页提取其他人的肖像。

发布目录仅为 `site/`。证书原图、简历原件、原始项目数据、密钥、模型权重及本机路径不进入发布目录。命名带 `-private` 等私有标记的文件不发布。网页的元信息、替代文本、注释和文件名同样应接受核对。

## 修改与验证

项目源码、架构、测试和 CI 链接使用各自独立仓库。Research-Code-Collection 只作索引与工程笔记入口；JSP 学习原型在 JSP-UI-Prototype 维护。调整项目结构前比对已公开 Git blob，保留来源和可恢复历史。

1. 先核对事实，再同步修改首页、公开简历和验证页；重大论文状态变更同时更新本仓库 README。
2. 在仓库根目录运行 `python tools/check_site.py`。新增外链先确认一手来源，按精确主机加入白名单，不使用通配域名。
3. 本机启动 `python -m http.server 8132 --bind 127.0.0.1 --directory site`，检查桌面和手机宽度的排版、长标题、作者换行、目录、图片及键盘焦点。
4. 对公开简历执行打印预览，检查分页、论文状态、资源入口和隐藏内容；打印版也不包含联系方式。
5. 通过 PR 审查变更，验证通过后合并。Pages 工作流仅从 `main` 发布 `site/`，PR 本身不部署。
6. 部署成功后访问正式网址，核对首页、公开简历、验证页、图片和自定义 404。记录实际核对日期，不把自动部署日期当成论文发表或获奖日期。

`check_site.py` 使用标准库执行文件、链接、静态内容和常见敏感特征检查。它不执行图片 OCR、事实验证、外网可用性检查或真实模型评测；这些项目需要对应的人工核对和实测记录。
